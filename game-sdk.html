Add rooms to your game.

Community games run in an isolated, sandboxed browser frame. The small Whosaid SDK connects your frame to a private room; it does not expose storage credentials or load game code on the Whosaid site origin.

Security model: only emit small JSON game events. The game owns its rules and validates every move. The room API transports messages and exposes only the state/actions your game explicitly publishes for its AI player.

1 · Add the SDK

Include this script in your ZIP’s root index.html. The SDK works only when the game is opened inside a Whosaid room.

<script src="https://whosaid.vercel.app/game-sdk.js" defer></script>

2 · Connect and exchange game events

async function startMultiplayer() {
  const room = await window.WhosaidMultiplayer.connect();
  console.log(`Playing in ${room.room} as ${room.playerName}`);

  window.WhosaidMultiplayer.on('event', (event) => {
    if (event.from === room.playerId) return;
    if (event.type === 'move') applyMove(event.data);
  });

  window.WhosaidMultiplayer.send('ready', { ready: true });
}

startMultiplayer();

The session contains room, gameId, playerId, playerName, and isHost. Register a listener with on(type, callback); use on('event', callback) to receive any player’s event. The callback returns an unsubscribe function. Event data must be JSON and is limited to 5 KB.

3 · Declare AI state and legal actions

A compatible AI agent can take turns only if the game publishes its current observation and allowed actions, and handles the returned agentAction event.

function publishTurn() {
  const state = { board: getBoard(), turn: getCurrentPlayer() };
  const legalActions = getLegalMoves().map(move => ({
    from: move.from,
    to: move.to
  }));
  window.WhosaidMultiplayer.publishAgentState(state, legalActions);
}

window.WhosaidMultiplayer.on('agentAction', (move) => {
  if (isLegalMove(move)) applyMove(move);
  publishTurn();
});

The game must publish fresh state/actions after each turn. The room API rejects any AI move that is not in the latest declared legal-action list; still validate game state transitions in your own game code.

Room and agent interface

  • Rooms require an unguessable friend-invite capability or player-session ID, support up to eight players, and expire after six hours.
  • Friend links let players choose a name and join. The host can create an AI invitation; it is a bearer capability and should only be shared with a trusted compatible agent.
  • The AI endpoint returns game, players, and agentState containing state and legalActions. Agent clients authenticate with the invitation token in an Authorization: Bearer … header.
  • To act, send POST /api/games with JSON {"action":"agent-move","code":"ROOM","move":{...}} and that authorization header. Poll GET /api/games?action=agent-state&code=ROOM for updates. Never put the token in a URL or share it publicly.

AI invitation links include a prompt template for compatible tools that can make HTTPS requests. An invite URL alone cannot make an arbitrary AI service compatible.
